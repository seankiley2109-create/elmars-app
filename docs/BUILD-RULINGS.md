# Build record: decisions and known small gaps

How Elmar's App v0.1.0 was built (3 Nov 2026): 16 planned tasks, each built by an agent in its own branch and gated by an independent review (often several fix rounds), then a whole-branch review and one final fix pass. This file keeps every decision Claude made on Sean's behalf, with what it costs if it was wrong, and every small issue deliberately left for later.

## Decisions (rulings)

- **R1** The controller ran `git init`, committed the docs to main, and branched to build/v1; Task 1 starts on build/v1 without git init — a brand-new repo needs a base commit and the build shouldn't sit on main — if wrong: trivial, rebase.
- **R2** Task 3's copy test may stub vault boot (`vi.mock` of lib/vault-boot returning `[{kind:'ready'}, noop]`) and set store `hydrated: true` — the test is about visible words, not boot — if wrong: a boot-screen word could slip past; Task 5's FirstRun copy is checked by its own review.
- **R3** `flushOnQuit(storage, win = getCurrentWindow())` takes an optional window with `onCloseRequested` and `destroy`, so it can be faked in tests — the plan's own test needs injection — if wrong: none (the extra parameter has a default).
- **R4** The `useToday` midnight test goes in `apps/web/src/lib/use-today.test.ts`, not hq-core — that's where the hook lives — if wrong: none.
- **R5** The TipTap Link extension must allow the `elmar` and `asset` protocols, and image `src` must accept `asset:` — otherwise mentions and attachments are stripped — if wrong: mentions are silently lost.
- **R6** `addNote` input gains optional `createdAt`, `updatedAt` and `folder`, used by the Evernote import — dedupe on created date needs them — if wrong: imports get today's date and dedupe breaks.
- **R7** Task 16's icon is generated from an SVG source (`tauri icon` accepts SVG), not a PNG — there's no image tooling on Windows — if wrong: swap for a PNG later.
- **R8** The model per task is sonnet for implementers by default and opus for T5, T6, T10, T12 and T13 (integration and design judgement); reviewers are sonnet, and the final review is opus — cost versus risk — if wrong: more fix rounds.
- **R9** Task 1 copied HQ's working tree, including Sean's uncommitted edits, not HQ's last commit — it's the newest state and its tests pass — if wrong: a half-finished HQ change came along; later tasks' tests would expose it.
- **R10** Task 3 widens the guard's term list with three more tool names from Sean's work — the same class the spec's anti-goal forbids — if wrong: a false positive on a generic word; easy to revert.
- **R11** Task 3 runs on opus rather than sonnet — it rewrites the store, routes and many components at once — if wrong: costs more.
- **R12** (Sean, in chat): run swarm-style. Independent tasks run in parallel, each in its own git worktree off build/v1; the controller merges each into build/v1 after its task review passes. This overrides the skill's no-parallel rule.
- **R13** ENML elements s/strike, code, pre, blockquote and sup get real conversions (~~, `, ```, >, plain text) instead of tripping fallback — spec §7 reserves the fallback for web clips and complex HTML, and over-triggering would attach "Original from Evernote.html" to ordinary notes — if wrong: a few more notes lose fidelity without the original attached.
- **R14** an Evernote task's dueDate is converted to the LOCAL calendar date of the instant, not the UTC date cut from the string — Elmar is in UTC+2, so cutting the UTC string puts midnight-local due dates a day early — if wrong: dates shift by one day for him.
- **R15** Task 13 minors 2 (adjacent bold/italic runs give ****), 3 (unknown named entities force needless fallback) and 5 (one bad base64 resource aborts the notebook) go into fix round 1 alongside Important 1 and rulings R13/R14 — each one directly hits real-export fidelity, which is the spec's anti-goal — if wrong: a slightly bigger fix round.
- **R16** printing never throws for user-enterable values. (1) Event title/location newlines collapse to a space in normalizeEvent (so canonical and round trip agree) and at the store boundary; (2) a 📍 in a title is escaped on print and unescaped on parse; (3) the same never-throw guarantee extends to task titles (newline collapse at addTask/updateTask and the task normalize) — same class of save-killer; (4) Task 5's vault writer must also catch a serialize() throw and report it through onSaveError, not only write failures (carried to T5 review/fix) — losing every save silently is the worst failure the spec names — if wrong: a title shows a space where a line break was pasted.
- **R17** Task 5 fix work starts in parallel with its review on three controller items: (a) Cmd+Q / app exit must flush — handle Tauri's RunEvent::ExitRequested in Rust: prevent exit, ask the frontend to flush, then exit; (b) syncFromDisk must NEVER overwrite in-memory state while writes are pending or failed — skip the reload and show the save-error toast instead; (c) the vault writer catches a serialize() throw and reports it via onSaveError (R16 item 4). Each is a silent-data-loss path the spec forbids — if wrong: extra Rust code that only a Mac can fully verify.
